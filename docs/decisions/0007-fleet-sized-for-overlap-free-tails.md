# 0007. 기단 규모를 기체 겹침 없는 배정에 맞춘다

- 상태: 승인됨, 적용됨 (2026-10-10, B7 수정)
- 관련: [bug-backlog B7](../exec-plans/active/bug-backlog.md), [ADR 0001](0001-domain-single-source.md) (rotation 구간)

## 맥락

합성 데이터 생성기는 기체를 편마다 `rng.choice(같은 기종 기체 목록)` 로 골랐다. 그 기체가 이미 다른 편에 묶여 있는지는 확인하지 않았다. 그 결과:

- fixture 하루치(2024-06-15)에서 146편 중 127편(87%)이 같은 기체의 다른 rotation 과 겹쳤다. 로컬 3년치 DB 에서는 129,836편이다. KE0005 가 ICN-ORD 와 ICN-HNL 에 같은 기체·같은 시각으로 있던 것은 가장 극단적인 경우다.
- 지연 전파 그래프의 edge 62개 중 53개가 buffer 음수였다. 0분 지연 트리거 146개 중 145개가 연쇄 지연을 만들었다.

겹침 없이 배정하려 했으나 기단이 모자랐다. 3년치 스케줄(161,868편)에서 기종별 최대 동시 필요 대수는 B737-800 49대(보유 20), B777-300ER 65대(보유 15)였다.

## 결정

1. **기체 배정**: 출발 순서대로, 비어 있는 같은 기종 기체 중 가장 최근에 돌아온 기체를 배정한다(best fit). 기체는 출발부터 `domain.rotation.aircraft_rotation_span` 동안 묶인다. 결항편도 계획상 기체를 잡는다. 쓸 수 있는 기체가 없으면 생성이 `ValueError` 로 실패한다.
2. **주 기종만 쓴다**: 노선의 `aircraft_types[0]` 만 쓴다. 대체 기종(`aircraft_types[1:]`)은 쓰지 않는다. 대체 기종을 쓰면 편의 기종·블록타임·승객 수와 예측 feature 가 바뀐다.
3. **기단 규모**: 기종별 필요 대수(3년치 최대 동시 대수)에 예비 10% 를 더해 올림한다.

   | 기종 | 이전 | 필요 | 결정 |
   |---|---|---|---|
   | B737-800 | 20 | 49 | 54 |
   | A321neo | 10 | 0 | 10 (주 기종인 노선 없음, 유지) |
   | B777-300ER | 15 | 65 | 72 |
   | B787-9 | 8 | 8 | 9 |
   | B747-8i | 5 | 4 | 5 |
   | 합계 | 58 | | 150 |

   출발 순서대로 배정하면 기체 수가 최대 동시 필요 대수 이상인 한 실패하지 않는다(구간 분할 문제의 greedy 최적성).
4. **인도일**: 모든 기체를 데이터 시작일(2022-01-01) 이전에 인도된 것으로 둔다.
5. **RNG 스트림 보존**: 예전 `rng.choice` 호출을 이전 기단 길이로 그대로 남기고 결과만 버린다. 그래서 `aircraft_registration`, `flight_number` 외의 값은 바뀌지 않는다. 3년치 161,868행의 21개 컬럼과 기상 이벤트 603건이 이전과 행 단위로 같다. 학습된 `models/delay_predictor.lgb` 는 다시 학습하지 않아도 된다 (feature 에 등록번호·편명 없음).
6. **편명**: (노선, 출발 slot) 마다 지역 번호 블록 안에서 겹치지 않는 번호를 준다. 같은 UTC 날짜에 같은 편명은 한 편뿐이다. Russia 블록은 Europe 과 겹치지 않도록 920 에서 940 으로 옮겼다.
7. **재발 방지**: `validator` 의 `no_aircraft_rotation_overlap`, `no_duplicate_flight_number_per_day` 를 오류(error)로 둔다.

## 합성 데이터의 알려진 한계

- **장거리 기체가 과다하게 필요하다.** 모든 편을 ICN 출발 왕복으로 보기 때문에([conventions](../conventions.md) ICN 출발 왕복 가정), 장거리 편 하나가 기체를 최대 32.7시간(ICN-JNB B777-300ER, `2·920 + 2·60` = 1,960분) 묶는다. 게다가 B777-300ER 가 주 기종인 노선이 29개다. 그래서 B777-300ER 가 72대가 되었다. 실제 대한항공 기단 구성과 크게 다르다.
- 기체 대수와 배정 방식은 시뮬레이션 결과에 영향을 준다. 하루마다 쉬는 기체가 있어서 시나리오 2(기체 교체)와 기체 재배정에서 예비기를 찾기 쉽다. best fit 배정이라 연속 편 사이 buffer 가 작다(fixture edge 32개, buffer 중앙값 27분, 최소 0분).

## 결과

- fixture 전파 그래프: edge 62 → 32, buffer 음수 53 → 0, 0분 지연 연쇄 145 → 0
- 비교 테스트([`test_consolidation_parity.py`](../../tests/test_domain/test_consolidation_parity.py))의 fixture digest 3개를 입력 데이터 변경 근거와 함께 갱신했다. 시뮬레이션 코드 동작을 고정하는 나머지 109건은 그대로다.
- 로컬 DB 는 `python scripts/generate_data.py --yes` 로 다시 만들어야 한다. 그 전에는 `validate_data.py` 가 새 오류 2건으로 실패한다.
