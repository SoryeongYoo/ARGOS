# ARGOS 디자인 시스템

**ARGOS** — *항공 노선 및 지상 운항 관제 시스템 (Airline Route & Ground Operations System)*
인천 허브 항공사(대한항공 모델)를 위한 AI 기반 **OCC(운항통제센터)** 의사결정 지원 도구. 포트폴리오 프로젝트. Python 3.12, Streamlit UI, LangGraph 멀티 에이전트 백엔드, OR-Tools 최적화, LightGBM 예측.

> 지연 감지 → 전파 시뮬레이션 → 회복 시나리오 3개 자동 생성 → OCC 관리자 최종 승인

이 디자인 시스템은 ARGOS의 시각 정체성을 정의합니다. 항공사 운항통제센터의 차분하고 기술적인 **한국어/영어 이중 언어** 미학과, 공식 OCC 사용자 흐름도에서 도출한 **라벤더 + 잉크 블랙** 크롬을 결합합니다.

## 제품 맥락

ARGOS는 항공사의 **핵심 OCC 워크플로우**를 구현합니다:

1. **대시보드** — 전 기재 KPI, 출발 스케줄, 노선 지도
2. **지연 예측** — LightGBM `P(지연 ≥ 15분)`
3. **전파 시뮬레이션** — 항공기 로테이션의 NetworkX DAG
4. **회복 시나리오** — 자동 생성된 *흡수 / 기재 교환 / 결항* 옵션
5. **UAM / ACROSS** — 한국 UTM을 통한 eVTOL 대체 경로

**안전 원칙은 변경 불가**: FAR 117 승무원 근무 한도는 하드 컨스트레인트이며, 모든 회복 조치는 인간의 명시적 승인이 필요합니다 (LangGraph `human_gate` 인터럽트).

서피스:
- **OCC 대시보드** (`src/argos/ui/dashboard.py`) — Streamlit, 두 개 탭 (운항 관제, UAM/ACROSS). 현재 코드베이스에서 유일한 라이브 UI이며, 나머지는 모두 서비스 레이어 Python입니다.

## 콘텐츠 기본 원칙

ARGOS는 소비자용 SaaS 마케팅이 아닌 **항공사 운항 매뉴얼** 문체를 사용합니다. 보이스:

- **이중 언어, 한국어 주도 헤딩, 영어 주도 기술 용어.** 사용자 향 카테고리는 한국어 레이블(`날짜 선택`, `항공편 필터링`, `회복 시나리오`), 모듈명·코드·ICAO/IATA 식별자·제품 마크(ARGOS, OCC, UAM, ACROSS, FAR 117)는 영어. README 자체는 두 언어를 자유롭게 혼용 — 이것이 하우스 스타일입니다.
- **절차적, 선언적.** 짧은 문장. 능동태. 코드베이스는 체크리스트처럼 읽힙니다: *"기재 재배정 최적화 (CP-SAT ILP). 혼란 발생 편에 기종 호환성과 시간 중복 없는 조건…"*
- **숫자는 표 형식이며 핵심 정보.** `161,868건`, `60개 노선`, `58대`. 단위는 항상 명시 (`분`, `NM`, `ft AGL`, `편`, `명`).
- **1·2인칭 없음.** "우리", "당신" 사용 금지. 주어는 *시스템* 또는 *항공편*. 초대가 아닌 상태 표시.
- **제품 UI에 이모지 없음.** 코드에서 사용하는 유일한 유사 이모지 문자는 비행기 마크 `✈`와 화살표 글리프(`→`, `▶`)이며, 그마저도 절제합니다. CSS `content` 기호와 유니코드 화살표는 허용; 이모지는 ❌.
- **액션 언어는 명령형 + 간결.** 흐름도 필 버튼: `날짜 선택`, `항공편 선택`, `승인`, `거부/중단`, `시뮬레이션 실행`. 동사 + 명사, 한글 8자 이하 또는 영어 2단어 이하.
- **안전 우선 한정어.** 위험 부담이 높을 때는 명시적 경고를 표면에 드러냅니다 — *"회복 조치는 반드시 인간의 명시적 승인 후에만 실행됩니다."* / *"FAR 117은 하드 컨스트레인트입니다."* 새 카피도 동일한 톤을 유지하세요.

**대소문자.** 헤더와 레이블은 문장 대소문자. ALL-CAPS는 코드 전용 (`ICN`, `RKSI`, `KST`, `CNX`, `KE001`, `HL7xxx`). 아이브로우 마이크로 레이블은 **대문자 + 0.08em 자간**.

**코드 형태의 값은 항상 고정폭** + 표 형식 숫자: 편명, 기체 등록번호, IATA 지연 코드, UTC 타임스탬프, 거리.

## 비주얼 기초

### 색상

팔레트는 **라벤더 + 잉크 블랙, 중립 흰색 배경**입니다. OCC 사용자 흐름도에서 직접 도출:
- 부드러운 **바이올렛** 사각형 → 화면 / 카테고리 헤더 표시.
- **잉크 블랙 필** → 운영자의 인터랙티브 액션 표시.
- 배경은 조용한 준흰색.

주요 브랜드 컬러: `--argos-violet-500` (`#8B5CF6`). 다크 CTA 컬러: `--argos-ink-900` (`#16161D`).

**시맨틱 / 운항 상태** 스케일이 상위 레이어로 적용됩니다: `--status-ontime` (초록), `--status-delay` (주황), `--status-critical` (빨강), `--status-info` (하늘). 이 값들은 대시보드의 항공편 상태와 1:1 매핑됩니다. 5개의 **모듈 액센트** (`--module-prediction`, `--module-sim`, `--module-recovery`, `--module-uam`, `--module-dashboard`)는 5개 OCC 워크플로우 단계를 상태 컬러와 경쟁하지 않으면서 태그합니다.

### 타이포그래피

| 폰트 패밀리 | 용도 |
|---|---|
| **Noto Sans** (가변, 굵기 100–900, 너비 62.5–100%) | UI, 본문, 헤딩 — 한글 + 라틴 이중 언어 지원 |
| **JetBrains Mono** (CDN) | 편명, 코드, 타임스탬프, KPI 숫자, 표 형식 데이터 |

스케일: `40 / 28 / 22 / 18 / 15 / 14 / 13 / 12 / 11`. 본문 **14px**, 테이블 **13px**, 대시보드 KPI 숫자 **40px** (표 형식 숫자). 헤딩 자간 `-0.02em` 조임; 아이브로우는 `+0.08em` 대문자.

### 간격 및 레이아웃

`4 / 8 / 12 / 16 / 20 / 24 / 32 / 40 / 48 / 64` px 스케일. 대시보드 레이아웃 관용구는 **2~3단 그리드** (지도 / 스케줄 / KPI), 이후 전체 너비 시뮬레이션 패널, 차트 스트립 — 명확하고 차분하며 마케팅 캐러셀 없음. 페이지에는 항상 **좌측 사이드바**(필터)와 **상단 탭 바**(모듈 전환)가 있습니다 (라이브 대시보드의 Streamlit 기본값과 일치).

### 테두리, 반경, 서피스

카드 및 패널: `--radius-lg` (12px), `1px` 헤어라인 테두리 (`--border-1`), 흰색 서피스. **버튼**은 필 형태 (`--radius-pill`, 흐름도 OCC 액션 스타일) 또는 정사각형 모서리 `--radius-md`. **입력** 은 `--radius-md`에 1.5px 포커스 테두리. 지도 / 차트 컨테이너는 `--radius-lg`와 부드러운 `--bg-2` 배경 틴트.

### 배경 및 이미지

제품 배경은 주로 평평한 흰색 (`--bg-1`), 보라색 틴트 보조 서피스 (`--bg-tint = --argos-violet-100`)는 하이라이트, 사이드바 헤더, 빈 상태, 카테고리 칩에 사용. **크롬에 그라디언트 없음.** 색상이 적용될 때는 단일 부드러운 보라색 워시 — 다중 스톱 무지개 그라디언트는 절대 금지.

이미지는 **데이터, 사진 아님**: Plotly 코로플레스, 지오 라인 트레이스, 히스토그램, OpenStreetMap 위 NetworkX 그래프. 실제 이미지는 **무채색 항공 촬영** (활주로, 터미널 내부, 하늘)으로 제한 — 따뜻한 히어로 사진은 없음.

### 애니메이션 및 상태

모션은 **기능적** — `--dur-fast: 140ms` (호버), `--dur-base: 200ms` (메뉴·탭), `--dur-slow: 320ms` (패널 표시). 이징은 `cubic-bezier(0.2, 0, 0, 1)` (표준), 주요 CTA용으로 약간 강조된 변형 있음. 바운스 없음. 스프링 물리 없음. 축하용 마이크로인터랙션 없음.

**호버** = 배경 틴트 미묘하게 변화. **누름** = 더 어두운 채움, 데이터 테이블에서 스케일 축소 없음; 필 버튼은 미세한 `scale(0.98)`. **포커스** = `--focus-ring` 바이올렛 글로우 (`box-shadow 0 0 0 3px rgba(139,92,246,0.35)`) — 키보드 내비게이션 접근성 필수.

### 그림자 및 엘리베이션

3개 그림자 토큰: `--shadow-1` (정적 카드), `--shadow-2` (부각), `--shadow-3` (모달 / 시나리오 카드). 필은 전용 `--shadow-pill`. 브랜드 틴트 `--shadow-violet`은 밝은 배경의 *주요* CTA 전용 — 장식용 금지.

### 투명도 및 블러

대부분 회피. 투명도 사용처: 상태 컬러 배경 (`*-bg` 토큰, 불투명도 ~10% 채도 — 이미 불투명, `alpha` 아님), 포커스 링 (`rgba(139,92,246,0.35)`), 그림자. 글래스모피즘 없음, `backdrop-filter` 없음. 운항 대시보드는 선명한 가독성이 필수.

### 고정 요소

- **사이드바**는 항상 존재, ~280px 너비, 흰색 서피스, 헤어라인 테두리 구분.
- **탭 바**는 메인 컬럼 상단에 위치; 탭은 정사각형 모서리, `--argos-violet-500` 언더라인 인디케이터.
- **푸터 힌트** (예: `DB: 161,868편 로드됨`)는 사이드바 하단 `--fg-3` 색상.

### 이미지 색상 느낌

차갑고 중립적인 방향. 따뜻한 필터 없음. 지도 기본값은 회색 육지, **앨리스 블루 바다** (현재 Streamlit 대시보드 코딩). 지도에 색상이 추가될 때는 상태 추적: 지연 편은 빨강, 정상은 하늘색, ICN 허브는 금색 별.

## 아이코노그래피

라이브 ARGOS 코드베이스에는 **아이콘 폰트, SVG 아이콘 세트, PNG 아이콘 에셋이 없습니다.** Streamlit 대시보드는 유니코드 글리프 인라인(`✈ ▶ → ✅ ❌`)과 Streamlit 색상 힌트(`:green[…]`, `:red[…]`)만 사용합니다.

**이 디자인 시스템은 [Lucide Icons](https://lucide.dev)** (CDN 로드)를 표준 아이콘 세트로 대체 사용합니다 — 동일한 획 굵기 (1.5px), 동일한 아웃라인 스타일, 차분하고 기술적인 보이스에 맞춤. *(이 대체를 명기 — 대한항공이나 인천국제공항공사에 내부 마크 라이브러리가 있다면 교체 가능.)*

규칙:
- **획 1.5px, 아웃라인 스타일만.** UI에서 솔리드/듀오톤 변형 금지.
- **아이콘 크기 기준:** 14px (본문 인라인), 16px (폼 필드·테이블 액션), 20px (사이드바 내비), 24px (KPI 모듈 마크).
- **색상은 문맥을 따름:** 기본 `--fg-2`, 호버 `--fg-1`, 활성 상태 `--argos-violet-500`, 상태 주석 아이콘은 상태 토큰 색상 (예: `AlertTriangle`은 `--status-delay`).
- **제품 UI에 이모지 없음.** README 유니코드 화살표가 한계.

**로고 / 워드마크.** ARGOS 코드베이스에는 고정 시각 로고가 없습니다. 대시보드 프로젝트 마크는 문자열 `ARGOS`와 `Airline Route & Ground Operations System`입니다. 이 디자인 시스템은 타이포그래피 로고 락업(Noto Sans, 700 굵기, `-0.02em` 자간)과 바이올렛 비행기 글리프 파비콘을 제공합니다. `assets/logo-argos.svg`와 디자인 시스템 탭 브랜드 카드를 참고하세요.

## 주의사항 및 알려진 대체

1. **아이콘 세트 대체:** 코드베이스에 네이티브 아이코노그래피가 없어 Lucide를 CDN으로 사용. 사용자에게 명기.
2. **모노 폰트 미포함:** JetBrains Mono는 Google Fonts CDN에서 가져옴. 사용자가 업로드하지 않음.
3. **프로덕션 로고 없음:** 워드마크 + 글리프는 타이포그래피 기반이며 확정된 브랜드 마크가 아님.
4. **단일 제품 서피스:** Streamlit OCC 대시보드만 라이브 UI. UAM/ACROSS는 별도 제품이 아닌 내부 두 번째 탭. 마케팅 서피스, 모바일 앱 등은 존재하지 않으며 투기적으로 설계하지 않음.
